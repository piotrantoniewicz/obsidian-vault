# The Context Box Do It, But Right

Al Iverson (ekspert od deliverability i DMARC) rozwija termin Dylana Redekopa „context box" — linijkę w mailu tłumaczącą odbiorcy, dlaczego dostaje daną wiadomość (np. „otrzymujesz tego maila, bo zapisałeś się do newslettera XYZ"). Chwali samą ideę jako ochronę przed skargami spamowymi, ale ostrzega przed jej złym wykonaniem: zbiorczy, „na wszelki wypadek" context box wymieniający wszystkie możliwe źródła zgody (zapis online, darowizna, wydarzenie, kontakt z organizacją) nic nie mówi odbiorcy i zdradza, że nadawca sam nie wie, skąd ma dane. Autor stawia twardą zasadę: jeśli nie da się zrobić context boxa precyzyjnie i zgodnie z prawdą, lepiej go pominąć niż zamienić w wizualny szum, który sam w sobie podważa zaufanie.

## Frameworki i metody

**5 warunków dobrego context boxa:**

1. **Be Specific** — pokaż tylko to jedno faktyczne źródło zgody danego odbiorcy, nie listę piętnastu opcji naraz.
2. **Be Accurate** — treść musi odpowiadać rzeczywistości; rozjazd z faktami odbiorca odczyta jako kłamstwo lub kupione dane.
3. **Be Permission-Based** — informowanie, że dane kupiono „w pełni legalnie", nie zmniejszy irytacji odbiorcy; legalny spam to nadal spam z perspektywy przycisku „zgłoś".
4. **Be Verified** — bez double opt-in (DOI) formularze bywają fałszowane lub „zbombardowane" zapisami; twierdzenie „zapisałeś się sam" może być nieprawdziwe.
5. **Be Useful** — cel to proste przypomnienie odbiorcy, skąd się znają; niejasny lub ogólnikowy opis nie chroni reputacji nadawcy.

## Wnioski
- Dobry context box buduje zaufanie precyzją i zgodnością z prawdą — zbiorczy, ogólnikowy wariant działa odwrotnie do zamierzonego celu i może zwiększać liczbę skarg spamowych.
- Brak double opt-in to ryzyko nie tylko prawne, ale i komunikacyjne — organizacja może nieświadomie okłamywać odbiorcę co do sposobu zapisu.
- Zasada „jeśli nie możesz zrobić tego dobrze, nie rób wcale" ma zastosowanie szerzej niż tylko przy context boxie — dotyczy każdego elementu maila mającego budować [[Zaufanie]] poprzez transparentność.

## Zastosowanie
Przy audytach szablonów mailingowych klientów warto sprawdzić, czy context box (linijka „dlaczego to dostajesz") jest precyzyjny per segment listy, a nie jeden uniwersalny zapis dla wszystkich. Jeśli organizacja nie ma jasnych danych o źródle zgody każdego kontaktu (brak DOI, wspólne importy list), lepiej rekomendować usunięcie context boxa niż jego generyczną wersję, która może zwiększać liczbę zgłoszeń spamowych i szkodzić reputacji nadawcy.
