# 🎙️ How I AI GPT-5.6 review, How a solo builder runs 247 local AI, and What an agent harness is and how to build one

Odcinek podcastu Lenny'ego zbiera trzy wątki: czym jest "harness" (kod otaczający agenta AI, budowany dla powtarzalnych zadań) na przykładzie triażu błędów w Sentry; jak solo-builder Alex Finn uruchamia flotę lokalnych modeli AI 24/7 na własnym sprzęcie, łącząc lokalne modele z Claude Code w pętli budowa-recenzja; oraz recenzję modelu GPT-5.6 Sol, który w benchmarku produktowym wypada praktyczniej niż Claude Fable, mimo że ten drugi jest "teoretycznie" bardziej inteligentny. Wspólny wątek: dopasowanie narzędzia (harness, model, sprzęt) do konkretnego zadania, a nie uniwersalne rozwiązanie do wszystkiego.

## Frameworki i metody

**Kiedy budować harness zamiast używać ogólnego narzędzia:**
- Buduj harness, gdy zadanie jest częściowo deterministyczne (stałe kroki, stałe narzędzia) i częściowo niedeterministyczne (AI ustala przyczyny, pisze raport).
- Dedykowane adaptery narzędziowe (np. własny adapter do Sentry zamiast pełnego dostępu MCP) są szybsze, tańsze i mniej podatne na "błądzenie" agenta.
- Kodowanie uprawnień w harnessie (np. tryb "tylko śledztwo, bez pisania kodu") eliminuje potrzebę przypominania o tym za każdym razem.
- Ustrukturyzowane artefakty (log zadania, brief, raport) zamieniają jednorazowe śledztwo w zasób dla całego zespołu.

**Zasada dopasowania modelu do zadania (Alex Finn):**
- Model wolny, ale najinteligentniejszy (np. GLM 5.2 na Mac Studio) do zadań tolerujących opóźnienia.
- Model szybki i "wystarczająco dobry" (Qwen 3.6) do zadań objętościowych.
- Lokalny model do pracy skanującej (co 20 minut), [[Claude Code]] raz dziennie ocenia, co jest realnym problemem — "lokalny model to BDR, Claude Code to closer".

## Wnioski
- Harness to po prostu kod poprawiający skuteczność agenta w konkretnym zadaniu — [[Claude Code]] i Cursor same są w istocie złożonymi harnessami; własny harness może mieć zaledwie kilka plików.
- Nieograniczona inferencja (a nie ROI per token) jest właściwym uzasadnieniem inwestycji w lokalny sprzęt AI przy zadaniach uruchamianych w pętli ciągłej.
- W benchmarku produktowym GPT-5.6 Sol wygrywa z Claude Fable praktycznością (lepsze prototypy, łatwiejszy w pracy tekst), ale [[Sonnet 5]] pozostaje preferowany do pracy głosowej agentowej.

## Zastosowanie
Koncepcja harnessu jest bezpośrednio przydatna przy budowaniu własnych pluginów Claude Code i automatyzacji procesów NGO — warto rozważyć budowę wąskich, wyspecjalizowanych narzędzi zamiast ogólnych promptów dla powtarzalnych zadań (np. triaż zgłoszeń, przygotowanie raportów).
