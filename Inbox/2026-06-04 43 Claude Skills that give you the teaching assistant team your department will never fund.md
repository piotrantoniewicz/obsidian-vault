You finish your syllabus the night before classes start. You build the first three lesson plans. You rewrite a rubric you swore you’d reuse from last semester.

Three weeks in, you’re rebuilding all of it. New section, new students, new “I’ll do it better this time.” You promised yourself you’d save the prompts that worked. You didn’t. So you’re typing them again, from scratch, like you do every August and every January.

That rebuild tax is what kills your teaching. It has nothing to do with how much you care.

Claude Skills end it.

A Skill is a reusable instruction set Claude reads automatically every time the task matches. You teach Claude your course, your students, your standards, your AI-use policy, your tone, one time. Then every lesson plan, every rubric, every email, every feedback comment runs through that same brain.

The prompt you spent forty minutes writing for that one good discussion guide last March is gone. The Skill version of it is sitting there waiting for you the next time you need a discussion guide. That is the whole difference.

This post is a library of 43 Skills built for the work college teachers actually do. Each one comes with a copy-paste prompt you can drop into Cowork or Claude Chat to set the Skill up in about two minutes.

---

How to build any Skill below.

1. Open Claude Cowork or Claude Chat.
2. Paste the prompt for the Skill you want.
3. Claude generates the Skill file automatically.
4. Save via Settings → Capabilities → Skills.

Before you build anything, build your ABOUT ME folder. Drop in your course context, your teaching philosophy, your AI-use policy, your standards-based grading scale if you use one, your communication tone with students. Every Skill below reads that folder before it runs. Without it you get good generic output. With it you get output that sounds like you.

One more thing before the list. Don’t try to build all 43 this weekend. Pick the three Skills that cover the work you hate the most. Build those. Use them for a week. Then come back for three more. The compounding starts the first time you reuse one. Don’t blow up your whole teaching system to do this.

## Category 1: Course Design and Planning

The work you do before anyone walks in the room.

---

## Skill 1. Course Blueprint Builder

Turns a course title and level into a complete course map. Learning outcomes, week-by-week topic sequence, assessment plan, and the throughline that ties it all together.

Why you use it. Most syllabi are built backward from the textbook table of contents. This Skill builds them forward from the actual outcome you want students to walk out with.

When to use it. The day you find out you’re teaching a new course or rebuilding an old one.

```markup
Help me create a Skill called "Course Blueprint Builder" that
turns a course title and level into a full course map.

When invoked, ask me for:
1. Course title, level (undergrad intro, undergrad advanced, grad)
2. Discipline and program context
3. Number of weeks and class meetings per week
4. The single biggest outcome I want students to walk out with
5. Required topics or accreditation constraints
6. My pedagogical approach (mastery-based, traditional, mixed)

Output:
- 4-6 measurable course learning outcomes
- Week-by-week topic sequence with the throughline
- Assessment plan mapped to each outcome
- Where AI use fits in each unit
- 3 design risks to watch for
- Suggested signature assignment that demonstrates the whole arc

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 2. Learning Objectives Writer

Generates measurable, Bloom’s-aligned objectives from a topic or unit. Action verbs that hold up to assessment. No more “students will understand.”

Why you use it. Vague objectives produce vague assessments and vague feedback. Sharp objectives make every downstream piece of the unit easier.

When to use it. Every time you build a new unit, week, or assignment.

```markup
Help me create a Skill called "Learning Objectives Writer" that
generates measurable, Bloom's-aligned objectives from a topic.

When invoked, ask me for:
1. Course and unit topic
2. Student level and prior knowledge
3. Bloom level I want students to reach (remember, understand,
   apply, analyze, evaluate, create)
4. How students will demonstrate it
5. Time available for the unit

Output:
- 3-5 objectives written with a measurable action verb
- Each objective tagged with its Bloom level
- A one-line "evidence of mastery" statement per objective
- 2 objectives I should cut if I have to trim scope
- Common verb traps to avoid (understand, know, appreciate)

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

When to use it. Two weeks before the semester starts. Or right now if you’re already late.

```markup

4. Required texts and tools
5. Course learning outcomes (paste from Course Blueprint Builder)

   encouraged in defined ways, integrated as required tool)

Output:
- Complete syllabus draft with section headers
- Plain-language AI policy section students can actually parse
- Communication norms section
- Schedule table mapped to outcomes
- Grading section that matches my stated philosophy
- 3 questions to push me to sharpen any vague sections

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 4. Lesson Plan Designer

Builds a single class session minute-by-minute. Activities, timing, materials, transitions, and the question you’ll ask if energy drops at minute 47.

Why you use it. Most lesson plans are a list of topics with no timing. This Skill produces a session you can actually run, with the activity transitions already mapped.

When to use it. The night before class. Or the morning of, if you’ve earned the right to wing it.

```markup
Help me create a Skill called "Lesson Plan Designer" that builds
a single class session minute-by-minute.

When invoked, ask me for:
1. Course and topic for the session
2. Session length and class size
3. Modality (in-person, online sync, hybrid)
4. The one thing students must leave understanding
5. What they were supposed to do before class
6. Materials and tech available

Output:
- Opening hook (3-5 minutes) that creates the question
- Minute-by-minute plan with activity, purpose, timing
- 2 active learning moments minimum
- Transitions between activities written out
- Built-in formative check at the halfway point
- Closing reflection that maps to the next session
- A "what to do if energy drops" backup move
- Materials list

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 5. Backward Design Mapper

Starts from the final assessment and works backward to daily lessons. The unit gets built from the artifact students produce. The textbook table of contents stays out of it.

Why you use it. Backward design is the most-cited and least-used pedagogy in higher ed. This Skill makes the process fast enough that you’ll actually do it.

When to use it. Every new unit. Every redesign of an old one.

```markup
Help me create a Skill called "Backward Design Mapper" that
starts from the final assessment and works backward to daily
lessons.

When invoked, ask me for:
1. Course and unit
2. Final assessment or artifact students will produce
3. Time available for the unit (number of class sessions)
4. Student prior knowledge entering the unit
5. The one demonstrable skill they must own by the end

Output:
- The criteria for "proficient" on the final artifact
- The skill ladder students must climb to produce it
- Daily session topics reverse-engineered from that ladder
- The formative check at the end of each session
- The practice loop that connects sessions
- 2-3 pre-unit diagnostic questions to assess starting point
- Where AI use accelerates vs. shortcuts learning in this unit

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 6. Lecture Builder

Turns a topic into structured lecture notes or slide outlines with examples and analogies. Built for the way you talk. The textbook author’s voice stays in the textbook.

Why you use it. Lectures decay. The example that landed in 2019 reads like a relic in 2026. This Skill rebuilds the examples to match the current students in the room.

When to use it. Any week you’re teaching a topic you haven’t taught in a year or more.

```markup
Help me create a Skill called "Lecture Builder" that turns a
topic into structured lecture notes or slide outlines.

When invoked, ask me for:
1. Course, topic, and session length
2. Student level
3. Three things they should walk out understanding
4. Current real-world contexts I want to anchor to
5. My usual pacing (lots of stops for discussion, fewer stops,
   pure delivery)
6. Visual style (text-heavy slides, image-led, minimal)

Output:
- Opening hook tied to current context
- 3-5 main sections with key points
- 2 examples and 1 analogy per section
- Built-in discussion prompts every 10-15 minutes
- A closing synthesis question
- Slide outline if requested with speaker notes
- Things to remove if I run short on time

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 13. Rubric Builder

Generates a criteria-based rubric (analytic or holistic) aligned to your objectives. Standards-based scale, descriptive language, no vague “good” and “excellent.”

Why you use it. Vague rubrics make grading take twice as long and produce inconsistent results across submissions. A clear rubric is the single biggest time-saver in your grading week.

When to use it. With every assignment, before students start working.

```markup
Help me create a Skill called "Rubric Builder" that generates
criteria-based rubrics aligned to objectives.

When invoked, ask me for:
1. Assignment description
2. Learning objectives the assignment assesses
3. Rubric type (analytic, holistic, single-point)
4. My scale (4-level mastery, 5-level, percentage, letter)
5. Whether I want process or product criteria
6. Length and format students will submit

Output:
- 4-6 criteria mapped to the objectives
- Performance descriptors per level, written in observable
  language
- Anchor examples per level
- Weight per criterion if analytic
- A student-facing version of the rubric
- An instructor-facing scoring notes version
- 3 calibration sample submissions described, one per level

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 14. AI-Resilient Assignment Designer

Redesigns an assignment so AI use deepens learning instead of replacing it. The differentiator most faculty have not built.

Why you use it. Most “AI-proof” assignments are actually just harder to fake. This Skill builds assignments where the AI use is the point.

When to use it. Every assignment you suspect is currently AI-vulnerable. Which is most of them.

```markup
Help me create a Skill called "AI-Resilient Assignment Designer"
that redesigns assignments so AI use deepens learning.

When invoked, ask me for:
1. The current assignment (paste it)
2. The learning objective it should hit
3. Where I suspect students are using AI to short-circuit
4. The cognitive lift I want students to actually do
5. AI tools I assume students have access to

Output:
- A diagnosis of where the current assignment is AI-vulnerable
- 3 redesigned versions, ranked low to high lift on me to deploy
- For each version: what the AI is allowed to do, what it is
  off-limits for, what the student must produce that proves the
  lift was theirs
- A documentation requirement students complete alongside the
  artifact (prompts used, decisions made, what AI got wrong)
- A rubric criterion that grades the AI-use process itself
- One-paragraph student-facing explanation of the assignment
  philosophy

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 16. Feedback Generator

Drafts specific, kind, rubric-aligned feedback on student work from your notes. You read the submission, jot 3-5 observations, the Skill writes the comment.

Why you use it. The bottleneck on feedback is your time. Your judgment was already there inside 30 seconds. Banking the translation step is what gets your weekends back.

When to use it. Every batch of submissions. Especially the long-form ones.

```markup
Help me create a Skill called "Feedback Generator" that drafts
specific, kind, rubric-aligned feedback on student work.

When invoked, ask me for:
1. Assignment context and rubric criteria
2. Student name (if I want it personalized) or anonymized ID
3. My raw observations (3-5 bullets is fine)
4. The rubric score or mastery level on each criterion
5. Tone (warm and direct, formal, encouraging)

Output:
- A 3-paragraph feedback comment
- Paragraph 1: what is working and why
- Paragraph 2: the specific thing to improve and how
- Paragraph 3: the next step and what good looks like
- A one-line summary at the top for skimmers
- A suggested revision deadline if reassessment applies
- Optional voice-memo-style script if I prefer to record

Always read my ABOUT ME folder first.
Save as a permanent Skill.
```

## Skill 22. Icebreaker and Community Builder

Creates first-day and ongoing community-building activities. Built for actual psychological safety, the kind that holds when something gets uncomfortable in week ten.

Why you use it. The community you build in week one determines how hard students push back when something challenges them later. This Skill builds that foundation on purpose.

When to use it. Day one. Then every 3-4 weeks for the rest of the semester.

```markup
Help me create a Skill called "Icebreaker and Community Builder"
that creates community-building activities for college courses.

When invoked, ask me for:
1. Course and class size
2. Modality
3. Stage of the semester (day 1, week 3, mid-semester, week 12)
4. The vibe I want (high energy, calm reflection, structured
   sharing, playful)
5. How long I can spend on it
6. Whether I want it to surface course-relevant content too

Output:
- 3 activity options ranked by risk level
- For each: setup, run instructions, debrief, time required
- A "low-risk first move" so quiet students can participate
- The norm I want to establish through the activity
```

## How to build the system around the Skills

The list is the inventory. The system is what produces the compounding.

Build in this order.

First, build your ABOUT ME folder. Your course context, your teaching philosophy, your AI policy, your standards scale, your tone with students. Every Skill above reads this first. Without it, every Skill produces good generic output. With it, every Skill produces output that sounds like you.

Second, build the foundation cluster. Skill 1 (Course Blueprint Builder), Skill 2 (Learning Objectives Writer), Skill 13 (Rubric Builder), and Skill 37 (Mastery Map Builder). These are the load-bearing Skills. Every downstream Skill gets sharper when these are clear.

Third, build the Skills for your highest-frequency work. If grading is your bottleneck, start with Skills 16-19. If lesson planning eats your evenings, start with Skills 4, 6, 20, and 21. If AI integration is the part you keep deferring, start with Skills 29-32.

The first Skill saves you 30 minutes. The twentieth saves you an entire grading weekend.

## FAQ

**What is a Claude Skill and how does it work?**

A Skill is a reusable instruction set saved as a markdown file. Claude reads it automatically when the task matches, without you re-explaining the process. Skills live under Settings → Capabilities → Skills.

**How long does it take to build and install a Skill?**

About two minutes. Paste the prompt, Claude generates the file, save it to your Skills folder.

**What should I build first?**

Your ABOUT ME folder. Course context, teaching philosophy, AI policy, tone with students, standards scale. Every Skill reads it. Without it, you get generic output. With it, you get output that sounds like you.

**How do Skills differ from regular prompts?**

A prompt disappears when the conversation ends. A Skill activates every time the task matches. Skills encode your process once and run identically every time.

**Can my department use the same Skills?**

Yes. Skills saved in a shared workspace are available to every faculty member. The shared ABOUT ME folder ensures every faculty member produces materials that hold the same standard.

**How do I know which Skills to build first?**

Pick the work you hate doing the most. The Skills that automate the work you avoid pay you back the fastest. Grading is the most common starting point. Lesson planning is the second.

**Does the quality improve on newer Claude models?**

Yes. Better instruction-following means Skills that produced 80% of what you wanted last year produce 95% now. Same prompt, sharper output.

**What if my institution restricts AI use?**

Then your AI policy is the first Skill you build. Skill 29 produces a defensible course policy that respects institutional constraints and gives your students clear guidance inside those limits.
